CLI reference

Every command, flag and default — as shipped in v0.6.0. Install: pip install spectrumalyzer plus ffmpeg on your system.

Overview

spectrumalyzer <command> [options]

analyze   Analyze an audio file and export beat/band data
report    Generate a self-contained HTML visual report
formats   List available export formats
trim      Cut the best short version of a long track (or video)
describe  Describe a track in natural language + mood tags
find      Semantic search over a folder of audio files
model     Manage the local embedding model (pull | status)
mcp       Run the MCP server (stdio) — spectrumalyzer as tools for AI agents

global:
  --version   print version

All commands read anything ffmpeg decodes: mp3, wav, flac, ogg, m4a, and even video files (the audio track is extracted automatically). Progress goes to stderr, data to stdout, so --stdout output is pipe-friendly.

analyze — the workhorse

spectrumalyzer analyze AUDIO [-o BASE] [-f LIST] [--fps N]
                        [--min-bpm X] [--max-bpm Y] [--no-bands] [--no-sections]
                        [--stdout] [--embed] [-q]
OptionDefaultWhat it does
--fps NnoneAdds true frame numbers to all exports. Required for remotion, hyperframes, ae, csv, fcpxml. Use 24/25/30/60 to match your project.
-f, --format LISTjsonComma-separated: json,remotion,hyperframes,ae,csv,fcpxml. Each file gets its own suffix under the base path.
-o, --output BASEaudio file nameOutput base path; every format appends its own suffix.
--min-bpm / --max-bpm60 / 200Tempo search window — constrain for unusually slow or fast music.
--no-bandsoffSkip frequency-band analysis (faster).
--no-sectionsoffSkip song-structure segmentation (faster).
--stdoutoffAlso write the first format to stdout (pipe-friendly).
--embedoffAdd a natural-language description + tags block to the JSON (uses the local embedding model; auto-pulls weights on first run).
-q, --quietoffSuppress progress output — for scripts and CI.
Example — everything, for a 24 fps film project
spectrumalyzer analyze soundtrack.flac --fps 24 \
  --format json,remotion,hyperframes,ae,csv,fcpxml \
  --min-bpm 70 --max-bpm 180 -o deliverables/soundtrack

report — see the music

spectrumalyzer report AUDIO [-o report.html] [--fps N] [--no-bands] [--no-sections] [-q]

Generates one self-contained HTML file (no server, no external assets): the waveform with the beat grid drawn over it, a band-by-time heatmap, the section strip, and all key stats. Perfect for client reviews, or for deciding where the edit's energy should go before you animate anything. Default output: <audio>.report.html.

formats — the cheat sheet

spectrumalyzer formats

Lists every export format, its file suffix, and what it's for. Full rundown on the Export formats page.

trim — a short version for video

spectrumalyzer trim AUDIO_OR_VIDEO [--length 90] [-o out.mp3] [--crossfade 0.5] [--preview] [-q]

Video tools and AI video models take short clips, not full songs. trim picks the most worthwhile window of your target length — loudness + onset density + section energy, with cuts snapped to the beat grid — and cuts the source with ffmpeg (short crossfades, no clicks).

OptionDefaultWhat it does
--length N90Target length of the short version, in seconds.
-o, --output PATH<name>-short.mp3 next to the sourceOutput path — container/codec follows the extension.
--crossfade SEC0.5Fade in/out at the cut points (0 disables).
--previewoffOnly print the chosen window; cut nothing.
Example — a 90 s bed from the full song
spectrumalyzer trim song.mp3 --length 90 -o bed.mp3
# Window: 37.50s → 127.50s (90.0s of 203.4s)
#   · best 90s window of 203s by loudness + onset density + section energy
#   · window covers the strongest overlapping section ('peak' section)
#   · cut points snapped to the beat grid
# Short version written: bed.mp3

If the source is a video file, the video is cut to the same window too: spectrumalyzer trim movie.mp4 --length 60 -o clip.mp4. When the track is already short enough, trim says so and writes nothing.

describe · find · model — semantic hearing

These three power the semantic layer: a small local embedding model that gives the measurements language.

# describe a track in words + mood/energy/flavor/use tags
spectrumalyzer describe song.mp3 [--fps N] [--top 3]

# semantic search across a library (recursive, cached index)
spectrumalyzer find "calm warm bed for a documentary intro" ./my-library [--limit 10] [--refresh]

# embedding model lifecycle
spectrumalyzer model pull     # download weights into ~/.config/spectrumalyzer/embedding/
spectrumalyzer model status   # preferred / fallback model + installed state

First use auto-downloads the weights (~90 MB, one-time). Everything runs locally — no audio or text ever leaves your machine.

mcp — tools for AI agents

spectrumalyzer mcp    # blocking stdio MCP server

Exposes analyze, describe, find, export, report, trim and model-status as native MCP tools. Registration snippets and the full tool table live on the MCP & agents page.

Troubleshooting & FAQ

"ffmpeg not found"

Install ffmpeg (brew / apt / winget) and make sure ffmpeg -version works in your terminal.

BPM is double or half what I expect

Heavily syncopated music can report the 8th-note pulse or the half-time feel. Constrain the search: --min-bpm 100 --max-bpm 140 for a house track you know is ~120.

bpmConfidence is low (< 0.5)

The pulse is unclear — ambient, live drums, or rubato material. The beat grid may drift; prefer onsets[] (raw hits) for such tracks, or widen the BPM window.

Beats feel slightly off on hi-hat-heavy music

That was the v0.1 problem — since v0.2 the grid anchors to the kick. Tracks with no low-frequency pulse (acoustic, choir) fall back to onset alignment (±12 ms).

Remotion export refuses to run

It needs --fps — frame numbers can't be computed without a frame rate.

Can it read video files?

Yes — any file ffmpeg reads, including MP4/MOV; the audio track is extracted automatically.

Where is the old spectrum key?

v0.1's "spectrum" was not a real FFT. Since v0.2 it's the real bands matrix; bpm, beats, beatTimes are unchanged. See the changelog.
